# Keiba（競馬の単勝予測・期待値・バックテスト）

`keiba_predictor` は、競馬の単勝について「1着確率を出す → 期待値を計算する → 期待値の高い馬だけ買う」を、
**未来の情報を混ぜずに**学習・検証するためのコードです。
競艇の予測コード（Masa-Forest/BoatRace の `feature_ablation.py`・`all_venue_v2.py`・`all_venue_v3.py`）の考え方を
競馬向けに作り直しました。

目標は「必ず勝つ」ではなく「**長い目で見て損をしにくい**」ことです。競馬の単勝は控除率が約20%あるので、
何も考えずに買うと回収率は約80%になります。100%を超えるには、市場（オッズ）より正確な確率が必要です。

## 使い方

```bash
pip install -r requirements.txt

# サンプルデータを作る（実データがなくても全部の流れを試せる）
python -m keiba_predictor sample --out data/sample.csv

# 時期をずらしながら検証（約10秒）
python -m keiba_predictor backtest --data data/sample.csv

# 全期間で学習してモデルを保存
python -m keiba_predictor train --data data/sample.csv --model models/keiba.pkl

# 出走表を予測（過去の結果も渡す。特徴量を作るのに使う）
python -m keiba_predictor predict --model models/keiba.pkl --history data/sample.csv \
    --entries 出走表.csv --out 予測.csv --min-ev 0.10

# テスト
python -m pytest
```

## データの形式（1行 = 1頭）

| 列 | 内容 |
|---|---|
| race_id | レースID（同じレースの馬は同じ値） |
| date | 開催日（YYYY-MM-DD） |
| venue | 競馬場（札幌・函館・福島・新潟・東京・中山・中京・京都・阪神・小倉） |
| surface | 芝 / ダート |
| distance | 距離（m） |
| going | 良 / 稍重 / 重 / 不良 |
| horse_id, jockey_id, trainer_id | 馬・騎手・調教師のID |
| horse_no, frame | 馬番・枠番 |
| age, sex | 馬齢、牡 / 牝 / セ |
| weight_carried | 斤量（kg） |
| horse_weight, weight_diff | 馬体重と増減（kg） |
| odds, popularity | 単勝オッズと人気 |
| finish | 着順（出走表、取消・除外・中止は空） |

`predict` の出走表も同じ列です（`finish` はなくてよい）。

## 構成

| ファイル | 役割 |
|---|---|
| `keiba_predictor/data.py` | 列の定義とチェック、サンプルデータの生成 |
| `keiba_predictor/features.py` | 未来の情報を混ぜない特徴量 |
| `keiba_predictor/model.py` | 1着確率のモデル（LightGBM のレース内ソフトマックス + 市場との組み合わせ） |
| `keiba_predictor/ev.py` | 期待値、ケリー基準、買う馬の選び方 |
| `keiba_predictor/backtest.py` | ウォークフォワード検証、回収率・90%区間・最大ドローダウン |
| `keiba_predictor/cli.py` | コマンドライン |
| `tests/` | pytest（未来の情報が混ざらないことのテストを含む） |

### 未来の情報を混ぜない決まり（features.py）

- 馬・騎手・調教師の過去成績は、**そのレースの開催日より前の日**の結果だけで作ります。
  同じ日の他のレースは、先に終わっていても使いません（発走時刻がないので、どちらが先かを正しく決められないため）。
- そのレース自身の着順は使いません。
- オッズは1段目のモデルには入れず、2段目で市場の見立てとして使います。
- テスト（`tests/test_features.py`）で、未来の着順・オッズや同じ日の他レースの結果を書き換えても、
  特徴量が変わらないことを確かめています。

主な特徴量: 過去の出走数・勝率・3着内率・平均着順（平均に縮めた値）、同じ馬場・同じ距離帯での成績、
前走の着順・前走からの日数・距離の変化、前走と直近5走の市場の評価、騎手・調教師の勝率、
それらのレース内での順位と平均との差。

### モデル（model.py）

1. **1段目**: LightGBM で「レースの中で誰が勝つか」をソフトマックスで学習します（競艇版の `SoftmaxGBM` と同じ考え方。
   出走頭数がレースごとに違っても動きます）。
2. **2段目（Benter 方式）**: `p ∝ exp(a·log p_model + b·log p_market)`。`p_market` はオッズの逆数をレース内で合計1にしたもの。
   a, b は1段目が学習に使っていない期間で決めます。市場はとても強いので、モデル単独よりこの方が損をしにくくなります。

### 期待値と買い方（ev.py）

- 期待値 `EV = p × オッズ − 1`。`EV > min_ev` の馬だけ買います（1レース1頭まで、期待値の高い順）。
- 確率がとても小さい馬（`min_p` 未満）やオッズが高すぎる馬（`max_odds` 超）は、確率の誤差が大きいので買いません。
- 賭け金は1点100円（flat）か、控えめなケリー（ケリーの 1/4、1点は資金の2%まで）。

### 検証（backtest.py）

1. 期間の最初の4割は学習だけに使い、残りを区間に分けて「その区間より前だけで学習したモデル」で予測します。
2. その予測を前半・後半に分け、**買い方は前半だけで選び、後半で確かめます**（後半は選ぶのに使わない）。
3. 回収率にはレース単位のブートストラップで90%区間を付けます。区間が100%をまたぐなら「勝てる」とは言えません。
4. 「1番人気を全部」「全馬を全部」と比べます。

## サンプルデータでの結果（`sample` の初期設定、後半 864 レース）

| 買い方 | 点数 | 的中率 | 回収率 | 90%区間 |
|---|---|---|---|---|
| 1番人気を全部 | 864 | 34.4% | 74.8% | 68〜81% |
| 全馬を全部 | 10,385 | 8.3% | 89.4% | 80〜100% |
| 選んだ買い方（EV>0、100円ずつ） | 469 | 5.3% | 148.9% | 97〜201% |

対数損失（小さいほど良い）は 市場 1.961 → 組み合わせ後 1.952 で、モデルが市場に少し情報を足せています。

**注意: これはサンプルデータの結果で、実際の競馬で勝てることを示すものではありません。**
サンプルの「市場」は、わざと少しノイズのある見立てにしてあるので、モデルが勝ちやすい作りです。
それでも回収率の90%区間は100%をまたいでいて、確実とは言えません。実データでは市場はもっと正確で、
競艇版でも正直に分けて確かめると回収率は約90%でした。

## 実データで使うときの注意

- **オッズのずれ**: データの単勝オッズは確定オッズです。実際に買う時点（締切前）のオッズとはずれるので、
  `min_ev` は 0 より余裕を持たせてください。
- **取消・除外**: 取消・除外の馬は行ごと除くか、`finish` を空にしてください。
- **同着**: 1着が2頭いるレースは学習から外します（払戻の計算もしていません）。
- 次の段階の候補: 複勝（払戻が幅で決まる）、発走時刻があれば同じ日の先のレースも使う、血統・調教・上がりタイムなどの特徴量。
